# Data and provenance

`raw/luth2.rdata` is the byte-for-byte historical file previously at the repository
root. Its hash is in `raw/manifest.csv`. It contains one data frame, `luth2`,
which combines a completed framing experiment with demographic (`.x`) and
political (`.y`) survey exports. This is an analysis file with derived columns,
not an untouched survey export. `uniq` is unique; `pcid.x` and `pcid.y` are
constant survey markers, not respondent identifiers. The analysis does not
rejoin the file or treat its two components as independent samples.

The field dates and source identities were verified against `dem.luth.sav` and
`party.luth.sav` under `../prospect_theory/data/luth/source/`. Matching uses the
experiment's `uniq` and each source's `identifier`. Every source row matches
one analysis-file row, and status and trimmed user-agent values agree. The
original exports do not add respondents to these components. The framing CSV
in that directory also contains only completed experiment records.

`validation/source_checks.csv` records source hashes, counts, matches, and dates.
`validation/variable_labels.csv` preserves labels and coding metadata relevant
to age, education, gender, and the political knowledge questions. The SPSS birth
year codes start with 1 = 2009 and descend in calendar year; hence birth year is
`2010 - qd7y`. The stored `ppage` copies `qd7y`, so it is one larger than
calendar-year age in 2009. Exact age still depends on birthday. Implausible adult
ages are missing in the exploratory covariate-availability diagnostic; they do
not exclude respondents from completion comparisons. Education codes identify
degrees and grade groups, not years of schooling.

The source user-agent field is at most 100 characters after removing fixed-width
padding. Strings at that width can omit version and engine tokens. The
classification reports that limitation and keeps unresolved strings unknown.
The first MSIE token takes precedence over appended MSIE tokens. IE8's
compatibility marker changes the installed-version sensitivity, not the main
advertised-version comparison. The parser's supported domain is the browser
families observed in this 2009 study; it is not intended for contemporary UAs.

The historical file already contains contact and network metadata. New outputs
contain only aggregates and variable documentation. Original SPSS and MTurk
respondent files are not copied into this repository. Retaining the historical
file does not confer new redistribution rights over it or over external files.

`validation/mturk_source.csv` and `validation/mturk_browser_counts.csv` summarize
an additional export in `../hidden`. Its two Qualtrics metadata rows are removed
before counting respondents; all remaining rows are finished. Browser versions
therefore cannot be used to estimate completion differences in that export.

Run `make validate-sources` to repeat these checks. Set `LUTH_SOURCE_DIR` and
`MTURK_SOURCE` if the files are elsewhere. The normal build uses the committed
historical data and aggregate validation outputs, so it does not require access
to sibling repositories. Public replication candidates and access requirements
are recorded in `docs/data_inventory.csv`.

The broader search is documented in `docs/additional_data.md`.
`validation/local_candidates.csv` records hashes and completion coverage for the
additional inspected exports. `validation/july_support.csv` and
`validation/july_browser_completion.csv` preserve aggregate feasibility checks
for the July 2017 MTurk file, including its 11 unfinished records.
`validation/jss_source.csv` records the downloaded public user-agent corpus's
hash and actual schema; it contains no completion outcome. Repeat these checks
with `make validate-extensions`, optionally setting `JSS_UA_SOURCE` to the local
JSS supplement. The raw external files are not required for the normal build.

The `validation/signal_*` snapshots are generated by `make import-signals`.
They support the expanded question-organized analysis without redistributing
source respondents. Source paths and hashes, record overlap, item/timer mapping,
and metadata coverage accompany the outcome summaries.
`docs/exposure_sources.csv` identifies and hashes the two instruments underlying
the item/timer map. The July slider blanks
include explicit Not Applicable selections. `make questions` generates the
analysis tables from these snapshots and the historical analysis; `make check`
adds exhibits, manuscript, tests, lint, and simulations.


The `signal_text_*` snapshots summarize March's two common open-ended prompts.
`docs/text_items.csv` maps the actual free-text fields and submission timers.
Person-level summaries average the two prompts before calculating uncertainty;
the two answers are not independent observations. Only counts and aggregate
moments are exported, not response text or respondent identifiers. The historical
March label Open was corrected to Choice + open probe: the choice-field and
narrative-text summaries are different outcomes.
